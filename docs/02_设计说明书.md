# 设计说明书 · 交通法规问答 Agent

> 概要设计 + 详细设计 + 数据库设计三合一。签名级契约在《接口文档》（04）；数据流的一页概览在 [README](../README.md)「核心数据流」，本文往下钻一层：模块职责、关键机制、数据结构、取舍。
> 结构性的「不许」由门禁自动执行（§4），不是口头约定。

## 1. 总体设计

### 1.1 形态与进程

两个进程、一条 HTTP 缝：

```
agent_service（宿主 :8001）──RagClient──HTTP──▶ rag_service（:8000）──▶ Milvus / 本地权重 / 台账
```

- `rag_service`：知识库服务本体 —— 建库、检索、生成都在这个进程；载模型、连 Milvus、落盘。
- `agent_service`：Agent 循环 —— 判地区、多轮工具调用、收尾、复核。不载模型、不连 Milvus；唯一的落盘是自己的会话记忆（挂载卷上的 SQLite；镜像里没有 torch、没有 pymilvus）。
- 方向单向：agent 侧只拿得到 `RagClient`（造不出 `LegalRAG`），rag 侧看不到 agent；两条都有 AST 门与子进程拦截门盯着。

切成两个进程的理由：Agent 的每一次检索/取条/生成都必须走明面上的 HTTP 契约，结构上不可能「伸手进」知识库内部；两边各自重启、各自换实现；评测的两臂（rag 单轮 vs agent 多轮）也正好是这两个进程的对照。

### 1.2 包与依赖方向

| 包 | 角色 | 依赖 |
|---|---|---|
| `rag_contracts` | 契约叶：域类型、7 个端口（ABC）、配置、LLM 客户端、埋点 | 不 import 任何自家包；import 它不拉重依赖 |
| `api_contracts` | rag HTTP 面：`openapi.json`（冻结）+ 薄客户端 `RagClient` + `regen.py` | 只被 import，不许反向 import 消费者 |
| `rag_service` | 知识库服务 | → `rag_contracts` |
| `agent_service` | Agent 循环 | → `rag_contracts`、`api_contracts`（不 import `rag_service`） |
| `mcp_server` | MCP 适配层：stdio → HTTP，只做转发 | → `api_contracts` |
| `eval` | 离线评测与变异自检 | → `api_contracts`（HTTP 臂）/ 直起 app（asgi 臂） |

方向由 `tests/test_architecture.py` 与 `tests/test_contracts_architecture.py` 逐条检查（§4）。

### 1.3 端口与装配点

7 个端口（`rag_contracts/ports.py`），换实现 = 换一个类：

| 端口 | 职责 | 当前实现 |
|---|---|---|
| `Embedder` | 向量化；另答「可用吗 / 指纹 / 模型名」三问 | `adapters/embedding.py`（bge-m3） |
| `Reranker` | 交叉编码器打分（`top_n` 可选整池或前 k） | `adapters/reranking.py` |
| `LLM` | `chat` / `stream`，重试与 usage 归一 | `rag_contracts/llm.py`（生成与 agent 共用一份） |
| `VectorStore` | 建集合、插入、三种检索（稠密/稀疏/混合）、`law_filter` | `adapters/milvus.py` |
| `RagService` | 检索/生成/取条/材料/统计的聚合门面 | `query/rag.py`（`LegalRAG`） |
| `IndexStatus` | 就绪判定所需的全部问句（指纹、过期原因、期望模型…） | `indexing/status.py` |
| `IndexBuilder` | 一次完整 build | `indexing/build.py` |

装配规则：**只在各自的 `container.py` 发生** —— rag 侧 11 个 `build_*`（store / embedder / reranker / chunk_set / indexer / library / status / retriever / generator / rag / pipeline）+ `readiness`；agent 侧 `rag_base_url` / `build_client` / `_open_sessions`（会话库）/ `_laws_at_boot`（法条清单）/ `build_agent_runner` / `boot_agent_runner`。业务代码只接收注入对象，不许自己 new 具体实现；测试靠这条塞内存假件。

## 2. 详细设计

### 2.1 建库管线（rag_service/indexing/）

```
docx/ + pdf/ ──sources──▶ parser ──▶ chunker ──▶ indexer ──▶ Milvus traffic_law + 磁盘产物
              （按后缀挑读者）（法→章→节→条，  （条=父块，     （稠密 + 稀疏）
                               sha1 门控）      段=子块）
```

- `parser`：段落 → 法→章→节→条（中文数字、目录页剔除、零宽字符清洗）；**sha1 门控**：源文件没变就跳过解析。
- `chunker`：条 = 父块（整条原文），段 = 子块（可检索单元，带 `part_index` / `part_total`）。父块不写向量库，装配时载入内存（`HybridRetriever.parents`，按 `parent_id` 索引）；Milvus 行里只有子块和 `parent_id` 指针。
- `indexer`：写稠密（bge-m3）+ 稀疏（服务端 BM25）；写索引快照 `法规知识库/index/index_meta.json`（块数、条数、嵌入模型名、权重指纹）。
- **就绪门**（`readiness`）：启动/调用前比对「docx/pdf ↔ 本地产物 ↔ 集合」三方（条数/块数/快照里的嵌入模型名），不一致自动重建。手动触发：`--rebuild` / `POST /reindex`。
- `ingest`：会话材料与永久入库的落盘与台账写入（§3.2）。

### 2.2 在线检索与生成（rag_service/query/）

- `dispatch.run(mode=...)` 是门面与 HTTP 的唯一分派点：`ask`（检索 + 生成）/ `search`（到重排为止，不花 LLM 的钱 —— 检索基线评测走这条）。
- `rewriter`：口语对齐与别名扩充（醉驾 → 醉酒 / 醉酒驾驶 / 醉酒后驾驶）。
- `retriever`（`HybridRetriever`）：稠密 + BM25 双路召回 → 服务端 RRF 融合（k 可配）→ `bge-reranker-v2-m3` 重排；`debug` 时附两路各自名次。重排不可用或抛异常 → 按融合序返回 + note。
- `generator`：强制引用式生成（`chat` / `stream` 两条），两条兜底答复（检索为空 / 无 LLM）；`stream` 的尾帧是完整 `Answer`，与 `chat` 的产出由离线用例锁死全等 —— agent finalize 的逐 token 中继经 `RagClient.answer_stream` → `POST /answer/stream` 消费这条通道。
- `Answer.render()`：正文（模型写的，含 `[依据N]`）+ 参考文献段（**代码拼的** —— 编号与原文的对应不经过模型的手）。这是「引用可机械核对」的前提。

### 2.3 Agent 循环（agent_service/）

```
region（本地 / 深圳 / 全国 → 法名范围；每轮入口，顺带重置轮内通道）
  → clarify（仅当开了澄清且沾到具体地区：interrupt 问一句；resume 从这头续跑，region 不重跑）
  → 主循环节点（模型自决：调哪个工具、几轮）
      ├─ search_law / get_article / search_materials（都走 RagClient 的 HTTP；检索带超时预算，超时归「检索超时」回执）
      ├─ 同参去重：与前面某一轮参数完全相同的调用跳过执行、回一句「已跳过」
      └─ 零证据闸 `_unearned_stop`：一轮没调工具就想收工 → 代码把话推回去再叫一次
  → 收尾节点（正文 + 逐条 [依据N]；开了逐字流时把生成端 delta 边收边推）
  → review（逐条判「被原文支撑？」→ 低分整篇降级）
  → trace（决策链 / 分段耗时，可选 Langfuse 上报）
```

- 工具执行是自实现的节点（不是通用 ToolNode）：回执要按通道渲染成增量文本（`LOG_*` 前缀，写方与轨迹解析方共引同一套前缀）。
- 多轮检索结果按 `parent_id` 合并去重（`merge.py`），同一法条不因多次命中而重复引用。
- **工具执行护栏**：①同一参数重发（`web_search` 除外，分页即换参）不再执行 —— 跳过并回一句「已跳过」，`call_keys` 按轮清零；②检索调用带 `AGENT_TOOL_TIMEOUT`（默认 15 秒）预算，超时回执单成一类（客户端抛 `QaTimeout`，与「连不上」分开）；③被拦下的调用（未知工具 / 参数不合法 / 法规无法确定 / 检索失败 / 检索超时 / 重复跳过）在 Langfuse 各落一笔 span（轻量版「被拦下也要落账」，不建表）。失败与超时不记 key，重试仍然放行。
- **会话记忆**：`thread_id = session_id`（不带 = 每次新 thread），checkpointer 只在生产装配（`boot_agent_runner`）接线 —— `sessions=None` 的裸 runner 与升级前逐位相同，这时传 `session_id` 反而报错（`SessionUnsupported`）。跨轮保留的只有 `conversation` 通道（问答对，供记忆复建）；轮内的 8 个归约通道（messages / search_log / external / materials / steps / usage / truncated / call_keys）在 region 节点用 `Overwrite` 每轮清零。
- **`conversation` 的唯一写入点是 review 节点**（硬规约）：任何产出答案的图路径都在 review 统一追加本轮问答（含降级后的文本；复核关闭的早退分支同样追加），护栏测试逐节点比对守护 —— 记忆与答案由同一写点落账，不散在多个节点；唯一不追加的是 runner 级无 LLM 降级（图没跑，没有图路径可挂）。
- **人在环澄清**：clarify 是图里唯一的 interrupt 源、节点本身不调 LLM；resume 值先 strip，空 / 全空白 / 未知一律回落到全国法；恢复时 clarify 同时带出 `region` 与 `region_scope`（region 节点不重跑，否则 scope 不会更新）；resume 前校验挂起的确实是澄清中断，不是则 `ResumeConflict`。
- **逐字流**：收尾节点只在 `stream_tokens` 为真时推 delta，且 delta 是**草稿** —— 复核可能整篇降级，`done` 才是权威；帧归并只有一处（`rag_contracts/domain/answer.py::drain`），无尾帧 → `QaError` 冒泡到 HTTP 层 error 帧收尾，不静默回退非流式。
- `web_search`（博查）已实现、有离线用例，在 `tools/registry.py` 里标 `llm_visible=False`（只实现、不示人），所以不在下发的 `TOOLS` 里 —— 挂回去是把这一位改成 `True` 的事，「未接线」这个状态在 README 里有台账。工具表引用 `schemas.py` 的 payload **同一对象**（保下发逐字节一致），别就地改那些 dict。

### 2.4 关键机制

| 机制 | 位置 | 要点 |
|---|---|---|
| 就绪门 | `indexing/readiness.py` | 三方比对，不一致自动重建；重活只在需要时发生 |
| 零证据闸 | `agents/nodes.py::_unearned_stop` | 「没查就收工」在代码层面不成立 —— 把缺什么写进正文也一样拦 |
| 同参去重 | `agents/nodes.py::_call_key` | 参数完全相同的工具调用不重跑（`web_search` 豁免）；只记成功调用的 key，失败/超时可重试；被拦下的调用各落一笔 Langfuse span |
| 末端复核 | `agents/review.py` | 逐条 `[依据N]` 判支撑，低于 `AGENT_REVIEW_MIN_SCORE`（默认 0.35，2026-10-10 判官批标定）整篇降级成复核结论；**检测力已按判官批标定**（README 台账 / 运维手册 §9）；同时是 `conversation`（跨轮记忆）的唯一写点（记忆与答案同点落账，见 §2.3） |
| 权重指纹 | `adapters/local_model.py` + 索引快照 | 权重目录「相对路径 + 大小 + mtime」摘要；三态：不匹配拒服务 / 显式放行（重建并写新指纹）/ 老快照 unknown 降级。启发式：防误换不防篡改 |
| 契约冻结 | `api_contracts/` | `openapi.json` 提交即冻结，漂移测试逐字节比对；`RagClient` 对 4xx/5xx 归一为 `QaError`、超时归 `QaTimeout`（其子类） |
| 会话 vs 永久 | `indexing/ingest.py` + 台账 | session：只进本次会话、答完即弃；permanent：干跑校验 → 写真源 → 落台账 → 重建生效 |
| 会话记忆（短期） | `agents/session.py` + `agents/graph.py` | checkpointer 只在生产装配接线；运行时 config 只有一个构造点 `make_run_config`（有会话才配 `thread_id` 与 durability）；SQLite 单连接 + 进程内锁，前提见 §3.3 |
| 人在环澄清 | `agents/clarify.py` | 图里唯一 interrupt 源；resume 值归一（空 / 空白 / 未知 → 全国）；`AGENT_CLARIFY` 默认关；resume 不会再次中断 |
| 逐字流 | `agents/nodes.py`（收尾节点）+ `RagClient.answer_stream` | delta 草稿 / done 权威；帧归并单点 `drain`；断流不重放 |
| 地方法规判定 | `rag_contracts/domain/laws.py` | `laws_of` 按法名标 `LawInfo.local`（agent 只消费这个标记，不再自带 `_LOCAL_MARKERS`）；判定规则硬编码在契约叶，后续可外置成清单 / 配置（未做） |

### 2.5 可观测

- `rag_contracts/observability/tracer.py`：`Tracer` 空基类 / `Recorder` 记 span / `traced` 装饰器 —— 不注入即零开销。
- Langfuse 在函数内 import，没装 extra 自动退化；rag 线性路不上报（镜像不含 langfuse）；agent 容器配了 `LANGFUSE_*` 即真上报。
- 终端侧：`--trace`（决策链）/ `--timing`（分段耗时），渲染的是 `AgentState` 里的轨迹数据。

## 3. 数据库设计

### 3.1 Milvus 集合 `traffic_law`

| 字段 | 类型 / 约束 | 含义 |
|---|---|---|
| `chunk_id` | VARCHAR(128)，主键 | 子块 id |
| `text` | VARCHAR(4096)，开分析器（jieba） | 子块文本；BM25 函数的输入 |
| `parent_id` | VARCHAR(128) | 指向父块（整条）的指针 |
| `law_id` | VARCHAR(128) | 法名归一后的 id |
| `law_name` | VARCHAR(256) | 显示名 |
| `version` | VARCHAR(64) | 收录版本（如 20210429） |
| `citation` | VARCHAR(256) | 引用串（法名 + 条号） |
| `chapter` / `section` | VARCHAR(256) | 章 / 节（可空串） |
| `article_no` | VARCHAR(64) | 条号（如「第九十一条」） |
| `article_index` / `part_index` / `part_total` | INT64 | 条序、子块在条内序号、条内子块总数 |
| `dense` | FLOAT_VECTOR(1024) | bge-m3 向量；可缺省 → 纯 BM25 模式 |
| `sparse` | SPARSE_FLOAT_VECTOR | BM25 稀疏向量，由 `text_bm25_emb` 函数在服务端生成 |

- 索引：`dense` → AUTOINDEX / COSINE；`sparse` → SPARSE_INVERTED_INDEX / BM25（DAAT_MAXSCORE，k1 / b 可配，默认 1.2 / 0.75）。
- 分词与 RRF 融合都在 Milvus 服务端（`MILVUS_ANALYZER=jieba`）；应用层只发查询文本 + 稠密向量，收 `(chunk_id, score)`。
- `law_filter` 是集合内的过滤表达式，不另建表。

### 3.2 SQLite 台账 `data/documents.db`

一张表 `documents`（上传台账），DDL 在 `adapters/sqlite.py`（`CREATE TABLE IF NOT EXISTS`，幂等）：

| 列 | 说明 |
|---|---|
| `doc_id` | 主键（12 位 hex） |
| `file` / `display_name` / `suffix` / `sha1` / `bytes` | 原始文件信息（sha1 查重） |
| `mode` | `session`（会话材料）/ `permanent`（永久入库） |
| `law_id` / `law_name` / `version` / `articles` / `paragraphs` | 解析出的法规元信息（非法规文件为空） |
| `status` | `ready` / `rejected` / `superseded` |
| `note` / `created_at` | 备注与时间 |

索引：`idx_documents_mode(mode, created_at)`。

### 3.3 SQLite 会话库 `data/sessions.db`

LangGraph checkpointer 的落盘文件（`langgraph-checkpoint-sqlite`；建表由库自己的 `setup()` 完成，幂等）：

- **单连接前提**：`open_sessions` 只开一个连接（`check_same_thread=False`）交给 `SqliteSaver`，外层用一个 `threading.Lock` 把**全部读写入口**（`get_tuple` / `list` / `put` / `put_writes` / `delete_thread` / `close`）包成 `_LockedSaver` —— 单连接 + 进程内锁是并发安全的前提；绕过装配另起 `SqliteSaver` 不在承诺内。
- 每个 thread（= 一个 `session_id`）存逐轮 checkpoint 与中断挂起：跨轮记忆与 resume 都从这里读；删文件 = 全部会话忘光。
- 无清理策略（长跑会一直长）—— 记在 §5 已知缺口。

### 3.4 磁盘产物

| 路径 | 内容 | 可重建 |
|---|---|---|
| `法规知识库/text/` | docx 与 pdf 抽出的纯文本 | ✅ |
| `法规知识库/parsed/` | 解析后的条款结构（jsonl） | ✅ |
| `法规知识库/chunks/` | 父子块（jsonl） | ✅ |
| `法规知识库/index/index_meta.json` | 索引快照：块数、条数、嵌入模型名、权重指纹 | ✅（重建时重写） |
| `data/documents.db` | 上传台账 | ❌ 原始记录 |
| `data/sessions.db` | 会话记忆（checkpointer 落盘） | ❌（删了即丢记忆） |
| `data/traces/` | 跑批轨迹（不进版本库） | ❌ |

## 4. 结构门禁

规则不靠自觉，随离线用例一起自动执行（`tests/test_architecture.py`、`tests/test_contracts_architecture.py`，AST + 子进程两种手段）：

- import 方向（agent ↛ rag、契约叶不反向、适配层只碰 `domain`）；
- 装配只在 `container.py` 发生；退役包名不许复活；
- 重依赖（torch 等）不许被 `import rag_service` / `import rag_contracts` 顺手拉起；
- 同一句文案只许写一遍；提示词教的工具与真给模型的工具必须一致；
- 契约包只许被 import，打包面 `packages.find` 双向比对。

`eval/mutations/` 四张表（retrieval / contract / gates / mcp）把每条规则改坏跑一遍 —— 门禁必须翻红，才算覆盖；全绿只说明「没抓到」，不说明「规则对」。

## 5. 选型理由与取舍

- **Milvus**：稠密 + 稀疏 + 服务端融合一次到位（BM25 函数、jieba 分析器、RRF 融合都在库内），应用层不用自己拼两路结果；代价是多了 etcd / MinIO / standalone 三件套，由 compose 兜底。
- **bge-m3 + bge-reranker-v2-m3 进程内**：权重随仓、检索全程不出网，评测与复现稳定；代价是约 4.6GB 权重与启动预热（`warm()`）。
- **LLM 只依赖 OpenAI 兼容协议**（全仓唯一碰 SDK 的地方是 `rag_contracts/llm.py`）：换供应商改 `.env` 即可；地区/复核可各自单独配模型（快慢、思考与非思考按角色分开）。
- **强制引用式 + 代码拼参考文献**：把「引用对不对」从生成质量问题降为机械核对问题 —— 复核闸与评测都靠它。
- **两进程 + 契约冻结**：多一跳 HTTP 的代价，换来结构上不可穿透的边界与可独立演进的评测两臂。

- **已知缺口（议过、有意先不做）**：WebSearch 端口化、DocumentRepo 端口化、全 DAG 闸 —— 等首次触发它的需求出现时一并做，避免为抽象而抽象。运行期另有两处观察项：`sessions.db` 无清理策略；`RagClient.answer_stream` 无超时（流式超时语义与 `answer()` 不同源，成因见《接口文档》§3.1）。
