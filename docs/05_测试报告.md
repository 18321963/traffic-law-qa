# 测试报告 · 交通法规问答 Agent

> 回答三件事：**测了什么、怎么跑、结果在哪**。数字与实测口径不在这里重复 —— 效果数据只在 [README](../README.md)「效果」，含口径须知。
> 判绿口径两条：命令退出码为 0 且输出里没有 F/E（整份落盘再判）；改了行为面的规则，还必须过**变异自检** —— 把规则改坏，门禁要能翻红。
> **「用例全绿」不等于「覆盖」**：接线断了、替身打歪了的情况下用例也会全绿 —— 这类事故只有变异枪能验出来。

## 1. 测什么：四道防线

| 防线 | 载体 | 防住什么 | 判据 |
|---|---|---|---|
| 离线用例 | `tests/`，`python -m pytest` | 协议与行为面：鉴权 / 额度 / CORS / 会话与清理 / 流式归并 / 材料台账 / PDF 读取 / 并发闸 / 题目桶只读比对等。全部离线：不碰 Milvus、不调模型，没有用例被跳过 | 退出码 + 无 F/E |
| 结构门禁 | `tests/test_architecture.py` · `tests/test_contracts_architecture.py`（随 pytest 同跑） | 架构冻结变成断言：六包 import 方向、装配点唯一、文案单点、工具面一致、打包清单与目录双向比对（明细见[设计说明书](02_设计说明书.md)§4） | 同上；失败会指名道姓 |
| 变异自检 | `eval/mutations/`，`python -m eval.mutations.run all`（四张表：`retrieval` / `contract` / `gates` / `mcp`） | 门禁自身的检测力：把某条规则改坏，对应的门禁必须翻红；不红＝漏检 | 改坏必须翻红 |
| 效果评测 | `python -m eval` · `eval.singlehop` · `eval.multihop` · `eval.corpus` | 检索与答题质量：域内指标 / 单跳两臂对照 / 跨法多跳 / 题集桶 | 报告对比；数字在 README「效果」 |

分工：离线用例管「协议没被改坏」，结构门禁管「架构没被绕开」，变异自检管「前两者的规则真的抓得住」，评测管「效果有没有变差」。任何一层都替代不了另一层。

## 2. 怎么跑

| 想验什么 | 命令 | 前置 |
|---|---|---|
| 离线用例（含结构门禁） | `python -m pytest` | 无 —— 全部离线可跑 |
| 变异自检（四张表一次跑） | `python -m eval.mutations.run all` | 无；改的是仓内源码、跑完即还原 —— 跑完核对 `git diff` 面，防变异残留 |
| 域内检索指标 | `python -m eval [--reference] [--pool N] [--http asgi\|URL]` | Milvus 与索引就绪；`--http URL` 则改为打已在跑的服务。检索臂不花 LLM 的钱 |
| 单跳 / 跨法多跳 | `python -m eval.singlehop` / `python -m eval.multihop` | 服务与模型端点（生成臂要调 LLM） |
| 题集桶重建 / 只读比对 | `python -m eval.corpus build\|check` | 题集源语料在 `data/` |

- 判绿：退出码 + 输出里的 F/E；输出整份落盘再判，不依赖汇总行（`addopts` 的细节见 README 测试一节）。
- 服务级冒烟（容器起来后探 `/health`、发一次问答、上一次材料）在部署与巡检动线上，步骤见[运维手册](../deploy/运维手册.md)。

## 3. 结果在哪

| 产物 | 在哪 |

## 4. 覆盖不到 / 已知缺口

- **模型输出质量本身**：单测管不了生成质量。这一面靠评测题集与复核闸兜底 —— 复核闸的检测力做过标定、阈值来历见[运维手册](../deploy/运维手册.md)§9；且复核分度量的是引用标签卫生，不是结论正确性。
- **无 CI**：回归靠本机全量 pytest + 人工核对改动面；流水线化在扩展计划里。
- **`integration` marker 还没有用例标它**：要真 Milvus / 真模型端点的路径不在离线面，由评测与冒烟覆盖。
- **前端**：没有自动化用例，靠手工走查与真实容器联调。
