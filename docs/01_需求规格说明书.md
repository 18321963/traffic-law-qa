# 需求规格说明书 · 交通法规问答 Agent

> 本文回答「系统要满足什么」。怎么用见《功能文档》（03），怎么实现见《设计说明书》（02），接口契约见《接口文档》（04）。
> 效果数字与实测口径不在这里重复维护，一律以 [README](../README.md)「效果」为准。

## 1. 背景与目标

- **问题**：交通法规查询。模型凭记忆回答法条不可靠、不可溯源；而法规文本本身有清晰结构（法 → 章 → 节 → 条），适合「检索原文 + 带引用作答」。
- **目标**：把「问题 → 检索法规原文 → 逐条引用作答」做成一个**可运行、可评测、可降级**的服务 —— 每条结论都能落回原文条号。
- **选型要点**（为什么是这套，取舍明细见《设计说明书》§5）：
  - 检索：混合（稠密 + BM25）+ 交叉编码器重排 —— 口语提问和精确术语/条号都要接得住；
  - 生成：强制引用式 —— `[依据N]` + 参考文献段由代码拼装，让引用**可机械核对**；
  - Agent 循环独立成第二进程 —— 多跳问题需要模型自决多轮检索，但结构上不许它伸手进知识库进程；
  - 检索全程离线、生成可选降级 —— 没有 key 或没有权重时，系统走短而不是走坏。

## 2. 范围与边界

**做什么**：建库（收录法规 → 向量库）、检索（混合召回 + 重排 + 精确取条）、问答（强制引用式生成）、Agent 循环（判地区 → 多轮工具 → 末端复核）、会话材料上传、四种入口（Python 库 / 命令行 / HTTP / MCP）。

**不做什么**：

- **不构成法律意见。** 输出是「法规原文的检索与引用整理」，仅供查阅辅助；法律适用与个案判断请咨询执业律师。
- **只答收录范围。** 当前收录 8 部法规（清单见 §5，「有哪些法规」以 `GET /laws` 为准）；未收录的法规、地方细则、司法解释一律明说「查不到」，不编。
- **不做时效保证。** 以收录版本为准（版本见文件名与 `GET /laws`）；联网时效已实现但当前未接线（见《功能文档》§3.4）。
- **不做问答之外的司法/行政能力**：责任认定、判决预测、法律文书生成等不在范围内。

## 3. 功能需求

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 降级可跑 | 三级降级，任何一级都不许「静默错答」：① 无 LLM key → 生成层拒答、检索照常；② 无本地权重 → 纯 BM25；③ 重排不可用或抛异常 → 按融合序返回并在 note 里留一句 |
| 性能 | 检索路不花钱、不出网；热态延迟为毫秒量级（三段 p50 实测：纯 BM25 4ms ｜ 混合融合 17ms ｜ 混合+重排 279ms，容器内，口径见 README「效果」） |
| 契约稳定 | rag HTTP 面冻结：`api_contracts/openapi.json` 提交即冻结 + 逐字节漂移测试；稳定性分级（稳定/内部/不承诺）见《接口文档》§0 |
| 可复现 | 全部离线用例一条不跳过（`python -m pytest`，约 12 秒，不碰 Milvus、不调模型）；评测题集与口径规则固化在 README |
| 可移植 | Python ≥ 3.10；基础依赖仅 3 个（openai / python-dotenv / httpx），其余按可选组装配；GPU 可选；两个服务镜像各取所需 |
| 凭据安全 | `.env` 不入库、不进镜像；模型权重指纹门禁记在索引快照里（防误换不防篡改，三态见《功能文档》§1.3） |
| 可观测 | `--trace` / `--timing` 终端渲染；Langfuse 为可选上报，未配置时行为与没有它逐位相同 |

> ⏳ **待填（维护者补）**：1）每部法规的**下载出处**（官方站点/公报页链接）；2）**收录时间**；3）**修订跟踪方式**（新版本发布后怎么发现、怎么替换）。
> 规则：替换/新增一律以 `docx/` 与 `pdf/` 为准 —— 放入源文件 → 重建索引 → 顺手更新上表与本节。
> PDF 走 `pdf` 可选组（`pypdf`）抽文本层；建库通道缺它会显式报错点名装法，不静默跳过。

**规模（当前）**：8 部 → 656 条 → 966 个可检索块（以 `GET /health` 的实时值为准）。
**本地权重**：`法规知识库/models/`，bge-m3（1024 维）+ bge-reranker-v2-m3，约 4.6GB；随仓分发，检索不出网。
**上传数据**：`data/documents.db` 台账（`session` / `permanent` 两态，状态 `ready` / `rejected` / `superseded`）；`session` 答完即弃，`permanent` 写进真源后重建生效。
**其他数据**：`data/` 题集与桶文件、`data/traces/` 跑批轨迹（不进版本库）。

## 6. 约束与假设

- 单机部署：Milvus（etcd / MinIO / standalone 三件套）由 `deploy/docker-compose.yml` 提供；业务进程不需要 GPU 也能跑（CPU 推理，慢一档）。
- 法规文本为公开政府文本；引用标注到「条」级（`[依据N]` → 法名（版本）+ 条号）。
- 换嵌入模型 = 必然全库重建，既有评测基线与该模型绑定、随换随废。

## 7. 验收方式

- **单元/离线**：`python -m pytest` —— 全离线、无外部依赖（约 12 秒；条数以实跑为准，本文不记数）。
- **效果**：评测题集（域内 82 题 / 跨法多跳 63 题 / 题面自带条号 112 题），数字与口径在 README「效果」。
- **结构**：结构门禁随离线用例一起跑；变异自检（把规则改坏必须翻红）：`python -m eval.mutations.run all`。
