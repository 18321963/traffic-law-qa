# 功能文档 · 交通法规问答 Agent

> 逐项回答「能干什么、怎么用、看到什么、边界」。一句话清单见 [README](../README.md)「做了什么」；签名级契约见《接口文档》（04）；本文是操作视角，命令可直接复制。
> 「边界」是本文重点：每条功能做不到什么、降级时会怎样，都写明白。
> 输出是法规原文的检索与引用整理，不构成法律意见（《需求规格说明书》§2）。

README「做了什么」表里的能力在这里按使用动线重排；结构类条目（端口化 / 出包 / 架构门禁）合并在 §5.4。

## 1. 数据与建库

### 1.1 建库管线

- **能干什么**：把 `法规知识库/docx/` 的法规原文变成可检索的 Milvus 集合（稠密 + BM25 稀疏），同时落磁盘产物（text / parsed / chunks / index）。
- **怎么用**：`python -m rag_service.cli.build build`；分步子命令 `parse` / `chunk` / `index` 可单独跑，`layers` / `docx` / `status` 看现状（短命令 `tlq-build`）。
- **看到什么**：各阶段报告（条数、块数、维度、耗时）；`build build --force` 强制重来。
- **边界**：docx 与 pdf 是建库真源，磁盘产物删了可重建；**sha1 门控**：源文件没变就跳过解析；换嵌入模型 = 必然全库重建、既有评测基线作废。

### 1.2 就绪门

- **能干什么**：服务启动/调用前自动比对「docx ↔ 本地产物 ↔ 集合」三方（块数、条数、快照里的嵌入模型名），不一致自动重建；一致就复用，不做无谓向量化。
- **怎么用**：无需操作（`qa()` 与 HTTP 启动都过这道门）；手动触发 `POST /reindex`（重建并热替换运行中的 runtime）或 `build build --force`。
- **看到什么**：`GET /health` —— 启动耗时、法规/条数/块数、通道与重排态、索引是否复用、就绪标记。
- **边界**：重建是全量向量化，花时间；只改代码不动语料时不会触发重建。

### 1.3 权重门禁

- **能干什么**：防「换了嵌入权重、索引还是旧向量」的静默错配 —— 建库时把权重目录指纹（文件名 + 大小 + mtime）记进索引快照，启动时核对。
- **怎么用**：正常无需操作；被拦时按 `/health` 的说明处理：`POST /reindex` 或 `RAG_ALLOW_REBUILD=1` 显式放行（放行即重建一次并写入新指纹）。
- **看到什么**：`/health` 三态：匹配 ｜ 不匹配（503，说明差在哪）｜ 老快照 `weights=unknown`（标 `degraded=true`，不拦）。
- **边界**：启发式 —— 防误换（换模型、换目录、残缺拷贝），不防篡改；拷贝/解压来的权重目录 mtime 会翻新，遇到这类误报用上面同一条命令解决。

### 1.4 上传入库（会话材料 / 永久入库）

- **能干什么**：把手上的 docx / md / txt / pdf 传进来 —— 只给本次会话用，或永久写进知识库。
- **怎么用**：`POST /documents`（multipart，`mode=session | permanent`）。
- **看到什么**：`GET /documents` 台账（mode、状态、条数、备注）；`DELETE /documents/{id}` 撤一份。
- **边界**：`permanent` 先干跑校验（不合格 `rejected` 并给理由，不写库），写进真源后要重建才生效；`session` 只进本次会话、答完即弃（agent 循环经 `/materials/search` 可查）。

## 2. 检索

### 2.1 混合检索

- **能干什么**：一个问题 → 稠密（bge-m3）与 BM25 双路召回 → 服务端 RRF 融合 → 候选池。
- **怎么用**：`python -m rag_service "问题" --search` / `POST /qa`（`mode=search`）。参数：`top_k`、`pool`（候选池深度，上限 `RAG_POOL_MAX`）、`law_filter`（限法，id 来自 `GET /laws`）、`debug`（两路各自名次与原始分）、`--no-vector`（只走 BM25）。
- **看到什么**：融合后的命中列表（`render()` 渲染条文摘录）；`debug` 加两路各自名次。
- **边界**：只答收录范围（8 部，见《需求规格说明书》§5）；**此路不花 LLM 的钱、不出网**；单通道召回 / 池子召回 / hit@k 的口径见 README「效果」的口径须知。

### 2.2 交叉编码器重排

- **能干什么**：对融合后的候选池用 `bge-reranker-v2-m3` 精排，截到最终 `top_k`。
- **怎么用**：默认开（`RAG_RERANK=1`）；`RAG_RERANK_TOP_N=0` 整池重排，设 k 只排前 k。
- **看到什么**：最终序与分数；效果数字在 README「效果」。
- **边界**：权重缺失或异常时**不报错**：按融合序返回 + note 里留一句；重排是延迟大头（三段 p50 见《需求规格说明书》§4）。

### 2.3 精确取条

- **能干什么**：已知条号（「第九十一条」「第 91 条」，或一句带条号的话）直接取原文，不经过检索排序。
- **怎么用**：`POST /articles/lookup`（`article_no` ± `law_name`，或直接给带条号的 `text`）；Agent 侧就是 `get_article` 工具。
- **看到什么**：那一条的原文 + 引用串；查不到**不报错**：200 + `found=false` + note 说明原因（含越界提示）。
- **边界**：条号解析支持中文数字与阿拉伯数字；法名歧义 / 条号越界给 note，不猜。

### 2.4 会话材料检索

- **能干什么**：在本次会话上传的材料里按重合度检索，供生成时引用。
- **怎么用**：`POST /materials/search`（query + doc_ids）；agent 循环里是 `search_materials` 工具。
- **看到什么**：`passages` 与渲染好的 `text`（带材料编号）。
- **边界**：只搜本次会话的 session 材料；`permanent` 走真源那条线（进索引，不再是「材料」）。

## 3. 问答

### 3.1 强制引用式生成（线性管道）

- **能干什么**：一次检索 + 一次生成：正文每条结论挂 `[依据N]`，末尾参考文献段由代码按检索结果拼装。
- **怎么用**：`python -m rag_service "问题"` / `POST /qa`（默认 `mode=ask`）；流式 `POST /qa/stream`（SSE：`evidence` 一发 + `delta` 真 token 流 + `done`）；只生成 `POST /answer`（自备检索结果，缺 `retrieval` 是 422），要逐字流就 `POST /answer/stream`（请求体同 `/answer`，SSE 出 `delta` + `done`）。
- **看到什么**：正文 + 参考文献（法名（版本）+ 条号 + 原文）；输出撞 `max_tokens` 被截断时 `notes` 里明说。
- **边界**：**编号与原文的对应不经过模型的手**（参考文献是代码拼的）；无 LLM key 走兜底拒答（检索照常返回）；rag 侧 `mode=agent` 已退役（422）—— 完整循环在 agent 服务（§4.1）。

### 3.2 Agent 循环

- **能干什么**：判地区（本地 / 深圳 / 全国 → 法名范围）→ 模型自决查什么、查几轮（`search_law` / `get_article` / `search_materials`）→ 收尾 + 逐条引用 → 末端复核。
- **怎么用**：`python -m agent_service "问题" [--trace] [--timing] [--json] [--max-steps N]`；`--http` / `RAG_BASE_URL` 指 rag 服务（默认 `http://127.0.0.1:8000`）。HTTP 面带 `session_id` 可跨轮（§3.5）；`AGENT_CLARIFY=1` 时沾地区先澄清（§3.6）；流式见 §3.7。
- **看到什么**：答案（+ 决策链 / 分段耗时）；服务形态见 §4.1。
- **边界**：**零证据不许停** —— 一轮没调工具就想收工会被代码闸推回去再叫一次（这类题会多付一次模型调用）；**同参重发不再执行**（回一句「已跳过」—— 提示词「换问法」规则上了代码闸）；检索调用带超时预算（`AGENT_TOOL_TIMEOUT`，默认 15 秒），超时与失败都只回执给模型换招、不自动重试；比线性管道慢、贵（多次模型调用），单跳问题用 rag 那条就够；CLI 与库调用每次独立（不带会话，见 §3.5）。

### 3.3 末端复核（降级保护）

- **能干什么**：生成后逐条判 `[依据N]`「是否被原文支撑」，不达标的整篇降级成复核结论。
- **怎么用**：默认随 Agent 循环走；复核模型可单独配（`AGENT_REVIEW_*`），阈值 `AGENT_REVIEW_MIN_SCORE`（默认 0.6）。
- **看到什么**：正常时答案不变；触发降级时整篇替换为降级答复（说明支撑不足）。
- **边界**：复核的检测力尚未标定（README 台账）—— 它是保护网，不是保险单。

### 3.4 联网时效（未接线）

- **能干什么**：`web_search`（博查 API）实现完整，用于「现行 / 最新」类问题。
- **怎么用**：⚠️ 当前**不在工具面** —— 启用要把 `tools/registry.py` 里 web_search 那行的 `llm_visible` 改成 `True`，并配 `BOCHA_API_KEY`。
- **看到什么**：启用后带来源的联网结论汇入答案。
- **边界**：未接线期间「时效」类问题只按收录版本作答，不联网。

### 3.5 会话记忆（跨轮）

- **能干什么**：同一 `session_id` 的多轮问答共享上下文 —— 下一轮的提示词里带最近几轮问答（`AGENT_HISTORY_TURNS` 默认 5，历史答案截 300 字）；轮内的检索日志 / 步数 / 用量不跨轮累积。
- **怎么用**：HTTP 请求带 `session_id`（`/qa` 与 `/qa/stream` 都支持；不带 = 每问独立，与升级前的单发逐位相同）。CLI 与库调用每次独立，不带会话。
- **看到什么**：响应 / `done` 帧里回抄 `session_id`；记忆落 `data/sessions.db`（compose 里挂 `tlr_sessions` 卷持久化）。
- **边界**：短期记忆只记问答对，不记材料（`session` 材料仍答完即弃）；删库文件 = 全部会话忘光，且无自动清理；runner 没开会话态时带 `session_id` 会被拒（HTTP 400）。

### 3.6 地区澄清（人在环）

- **能干什么**：问题里点出具体地区（如「深圳」）时，先中断问一句「按该地法规还是只按全国法」，拿到答复再作答；一轮至多问一次。
- **怎么用**：服务侧 `AGENT_CLARIFY=1`（deploy compose 的 agent 服务与 Studio 默认开，代码默认关）。非流式：`/qa` 返回 `status=interrupted`，拿 `session_id` 调 `POST /qa/resume`；流式：`/qa/stream` 出 `interrupt` 帧，调 `POST /qa/resume/stream`。请求形状见《接口文档》§3.2。
- **看到什么**：中断载荷里有地区名、提示语与库内相关地方性法规清单；resume 后按所选范围作答，选全国时答案 `notes` 里写明未叠加地方性法规。
- **边界**：`region` 值空 / 全空白 / 未知一律回落到全国法（不报错）；resume 不会再次中断；`AGENT_CLARIFY=0` 时图里没有这个节点，离线评测与裸调零变化。

### 3.7 流式输出（SSE）

- **能干什么**：把一轮问答的过程实时推给客户端 —— 轮次事件（走到哪个节点、调了什么工具）、答案逐 token 的 `delta`、中断、定稿。
- **怎么用**：`POST /qa/stream`（可带 `session_id`）；澄清恢复用 `POST /qa/resume/stream`。`curl -N` 直看原始帧；帧的种类与字段见《接口文档》§3.2。
- **看到什么**：`step`（含工具回执与检索摘要）/ `delta`（正文片段）/ `interrupt` / `done`（复核后的完整答案 + `request_ms`）；出错或未走完以 `error` 帧收尾（没有 `done`）。
- **边界**：**`delta` 是草稿，`done` 才权威** —— 复核若整篇降级，`done` 的正文与 delta 拼接可以不一致，属正常；断流不重放 delta；delta 只在收尾阶段（检索与决策期只有 `step`）。

## 4. 服务与集成

### 4.1 HTTP 服务面（两个进程）

- **能干什么**：rag 服务 10 个端点（`/qa` · `/qa/stream` · `/answer` · `/answer/stream` · `/health` · `/documents` · `/reindex` · `/laws` · `/articles/lookup` · `/materials/search`）；agent 服务 5 个（`/qa` · `/qa/stream` · `/qa/resume` · `/qa/resume/stream` · `/health`）。
- **怎么用**：`docker compose -f deploy/docker-compose.yml up -d --build`（rag 宿主 :8000；agent 宿主 :8001 → 容器内 :8000）；裸跑：`python -m rag_service.cli.serve` / `python -m uvicorn agent_service.api.app:app --port 8001`。
- **看到什么**：逐端点的参数与返回见《接口文档》§3。
- **边界**：agent 的 `/qa` **不是** rag `/qa` 的代理 —— 语义是完整循环（多轮工具 + 复核，body 多 `doc_ids` / `session_id`）；会话与澄清语义见 §3.5 / §3.6；机器可读契约（`openapi.json`）只覆盖 rag 侧；agent `/health` 读的是 rag 的可达性（rag 断掉它变 degraded / unhealthy）。

### 4.2 库 / 命令行入口

- **能干什么**：一套内核四种用法 —— 库（`from rag_service import qa`）/ 命令行 / HTTP / MCP。
- **怎么用**：命令清单见 README「入口」（`tlq-qa` / `tlq-build` / `tlq-serve` / `tlq-eval` 是短命令）。
- **看到什么**：`--help` 只打印用法，不碰磁盘、不连 Milvus。
- **边界**：库入口只承诺 `qa` / `render` / `QaError`；`import` 不拉重依赖（基础依赖仅 3 个包）。

### 4.3 MCP 适配层

- **能干什么**：把工具面喂给任意 MCP 客户端，5 个工具：`rag_search` / `rag_ask` / `rag_get_article` / `rag_laws` / `rag_search_materials`。
- **怎么用**：`python -m mcp_server`（stdio）；`--list-tools` 离线打印工具表；`--base-url` / `RAG_BASE_URL` 指服务地址。
- **看到什么**：工具返回即服务端响应原样透传（进出一律 dict）。
- **边界**：本进程不载模型、不 import SDK（SDK 只在运行时导入）；服务不在线时工具报连不上；stdio 强制 UTF-8（中文不乱码）。

### 4.4 服务契约

- **能干什么**：rag HTTP 面有机器可读契约（`api_contracts/openapi.json`）+ 配套薄客户端（`RagClient`）。
- **怎么用**：`from api_contracts.client import RagClient`；改完接口 `python -m api_contracts.regen` 重出。
- **看到什么**：漂移测试逐字节盯着 `app.openapi()` 与提交的 json；客户端 4xx/5xx 一律抛 `QaError`。
- **边界**：契约冻结只覆盖 rag 侧 HTTP 面；稳定性分级（稳定 / 内部 / 不承诺）见《接口文档》§0 —— 标「不承诺」的部分改了不打招呼。

### 4.5 演示台（Studio）

- **能干什么**：LangGraph Studio（`langgraph dev`）把 agent 图拉成可视化演示台：逐步看节点、在澄清中断处点恢复、改输入直接重跑。
- **怎么用**：
  1. 装：`pip install -e ".[agent,studio]"`（`studio` 组只给演示，不进 `all`）；
  2. 起：先确保 rag 服务在线（启动时要读一次 `GET /laws` 取法条清单），再在仓库根跑
     `PYTHONUTF8=1 PYTHONIOENCODING=utf-8 NO_PROXY=127.0.0.1,localhost langgraph dev --port 2024 --no-browser --allow-blocking`；
  3. 用：浏览器开 2024 端口，输入用模板 `{"question": "…", "stream_tokens": false}`；发一条带地区的问题 → 界面停在 `interrupt` → 用 resume 值 `{"region": "national"}`（或 `{"region": "深圳"}`）继续。
- **看到什么**：节点级执行与状态增量、`interrupt` 停在澄清节点等恢复。
- **边界**：演示形态不是服务形态 —— thread / checkpointer 由平台自己管（不经服务侧的会话库配置），也没有逐字流（`stream_tokens=false`，收尾走非流式；看逐 token 用 `/qa/stream`）；澄清强制开。Windows 实测的三件套各堵一个坑（`PYTHONUTF8`：.env 中文按 GBK 读会炸；`--allow-blocking`：图里的同步 HTTP 调用会被平台拦下；`NO_PROXY`：本机 rag 调用别绕代理），细节在《接口文档》§7。

## 5. 工程保障

### 5.1 可观测

- **能干什么**：终端决策链与分段耗时（渲染 `AgentState`）；可选 Langfuse 云上报。
- **怎么用**：`--trace` / `--timing`；agent 加 `--langfuse`；`LANGFUSE_*` 配了即上报（agent 容器默认开；rag 镜像不含 langfuse，不上报）。
- **看到什么**：每步的节点 / 工具 / 耗时 / 检索日志；Langfuse 里的 traces。
- **边界**：Langfuse 是可选 extra，没装没配时行为与没有它逐位相同；分数 / 排名 / 通道留在 `search_log`，进不进提示词由渲染层定。

### 5.2 降级可跑

- **能干什么**：三级降级让系统「差也差得能用」—— 无 LLM key → 生成层拒答 / 检索照常；无本地权重 → 纯 BM25；重排异常 → 融合序 + note（总表见《需求规格说明书》§4）。
- **怎么用**：无需操作（自动）。
- **看到什么**：兜底文案与 note；`/health` 的通道态。
- **边界**：每一种降级都在输出或 `/health` 里说得出来 —— 没有静默错答。

### 5.3 评测与自检

- **能干什么**：域内检索指标（82 题）、单跳两臂对照、跨法多跳（63 题）、题面自带条号（112 题）；结构门禁 + 变异自检。
- **怎么用**：`python -m eval [--reference] [--pool N] [--http asgi|URL]`；`python -m eval.singlehop` / `eval.multihop` / `eval.corpus build|check` / `eval.mutations.run all`。
- **看到什么**：指标报告；数字与口径在 README「效果」（含口径须知）。
- **边界**：改 gold 可离线重打分（轨迹里存着候选 id）；改题面则旧轨迹作废、只能重跑。

### 5.4 结构门禁

- **能干什么**：把架构规矩变成自动检查 —— import 方向、装配点唯一、重依赖不随手拉起、文案单点、提示词工具一致（明细见《设计说明书》§4）。
- **怎么用**：随 `python -m pytest` 一起跑；规则改坏用 `python -m eval.mutations.run all` 看门禁是否翻红。
