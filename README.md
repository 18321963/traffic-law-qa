# 交通法规问答 Agent

面向驾驶员 / 驾校学员 / 交管客服的交通法规问答。用大白话问，拿到**每句都挂着法条出处**的答案。

不是一个调 API 的脚本，是一条完整管道：**docx 解析 → 结构层 → 切块 → 向量索引 → 混合检索
→ 强制引用式生成**，外加一层 Agentic RAG（模型自己决定查什么、查几轮）。6 部法规、508 条、812 个检索块，
从原始 docx 一路建到可问答，中途每一层都能单独跑、单独验。

## 效果

三套题集测的不是同一件事，数字**不可跨表比较**（这是这类项目最容易犯的错）。
下表第三行不是新题集，是第一行那 82 道上的两臂对照：

| 题集 | 规模 | 测什么 | 结果 |
|---|---|---|---|
| 域内问答 | 82 题 | 检索命中率 | hit@1 **69.5%** · hit@3 **84.1%** · hit@6 **91.5%** · MRR **0.777** |
| 题面自带条号 | 112 题 | 能否绕过检索直接定位 | 唯一定位 **107/112**，其中取对 **107/107** |
| 单跳题 · 两臂并排 | 82 题 · `qwen-flash` | agent 值不值（同预算比首轮） | hit@1 69.5% → **73.2%**，hit@3 / hit@6 与 rag 持平 |
| 跨法多跳 | 63 题 · `qwen-max` | 一个答案横跨两部法 | 全预算 59/126 → **68/126**；同预算 **59/126 vs 59/126 打平**，多中的 9 条全靠多查一轮（1.0 → 1.7 次） |

> ⚠️ **第一行那组数不是"这个项目的属性"，是"这套配置的属性"** —— 它随向量模型变。
> 同一条管道，云端 `text-embedding-v4` 跑出过 hit@1 75.6% / MRR 0.805，换成默认的本地
> `bge-large-zh-v1.5` 就是上面那组：**白嫖、不出网**，代价是 hit@1 低（旧口径下 −4.5pp）。
> 完整对照见 [设计文档](docs/DESIGN.md) 第 6 节。
> 引用这些数时**带上向量模型**，否则两个人可以都没说错却对不上。
>
> 第三行还得**带上 LLM**：agent 那一臂的检索词是模型自己写的，换个模型这格就会动。
> 那一行用的是 `qwen-flash`，表头默认的 `qwen-max` 跑不出同一组数。
>
> 第四行两组数**要一起读**：全预算 agent 68/126 看着比 rag 的 59/126 高 7pp，可它是用 **1.7 次**
> 检索换来的 —— 多打几枪本来就会多中。把两边都只看第一次检索，两边**一模一样**，
> 说明 agent 在这题上没有「查得更准」，那 9 条全部来自「愿意再查一次」。
> 另有一个数没进表：agent 查到 68 条、最终**只引用了 61 条** —— 找到不等于用上。
> 题集的来历（从 100 道里删掉 37 道根本不多跳的）见 [设计文档](docs/DESIGN.md) 第 9 节。

这些数字是**可复现的**：358 条测试全部离线跑（不连 Milvus、不发网络请求），
其中一批直接钉住知识库的 golden 规模（6 部 / 508 条 / 812 块 / 均长 78.8 字）——
解析或切块逻辑一改坏，测试先红，而不是等评测数字悄悄掉下来。

## 跑起来

```powershell
# 1) 依赖
pip install -e ".[all]"

# 2) 起 Milvus（etcd + MinIO + Milvus，首启约 60~90 秒）
docker compose up -d --wait standalone

# 3) 向量模型（默认跑在本地 Ollama，拉一次就行，之后检索不出网）
ollama pull dengcao/bge-large-zh-v1.5

# 4) 配模型（没有 key 也能跑：退化为一套可用的 BM25 关键词检索）
Copy-Item .env.example .env    # 填 LLM_API_KEY 即可 —— 向量那几行已指向本地 ollama

# 5) 建库（docx 的 sha1 没变就自动跳过解析）
python -m traffic_law_rag.pipeline build

# 6) 问（这一步带一致性检查：docx 变了会自动重建，不用手动 build）
python -m traffic_law_rag "醉驾怎么处罚"
```

`pip install` 同时装了两个短命令：**`tlr-qa "醉驾怎么处罚"`**（等价第 6 步）和 **`tlr-serve`**（起 HTTP 服务）。

服务也可以整个进容器，连 Milvus 一起起来（`app` 服务，8000 端口）：

```powershell
docker compose up -d --build     # 起 Milvus + 应用；日志看 docker compose logs -f app
```

容器里有两处 `.env` 的值**必须**被覆盖，compose 已经写好了：Milvus 用服务名 `standalone` 而不是
`localhost`，embedding 端点用 `host.docker.internal:11434` 而不是 `localhost` —— 容器里的 localhost
指容器自己，两处都连不上。后一处尤其阴：**它不报错**。检索层按设计退回纯 BM25，服务照常起来、
`/health` 照常报「稠密+BM25」（那个字段只看配置与集合 schema，不探测端点），只有启动日志里
「稠密通道预热」那行会变成「未执行」—— 一个不失败、只是悄悄劣化的缺口，就是这个项目在
[设计文档](docs/DESIGN.md)里反复提防的那一类。

也可以当库用，一个口子：

```python
from traffic_law_rag import qa

print(qa("醉驾怎么处罚").render())                # 检索 + 生成
print(qa("深圳 行人在机动车道 罚款多少", mode="search"))   # 只检索，不花 LLM 的钱
```

## 它长什么样

真实输出，`qa("醉驾怎么处罚")` 的节选（省略号处略去，未改动措辞）：

> 醉酒驾驶机动车的，由公安机关交通管理部门约束至酒醒，**吊销机动车驾驶证**，**依法追究刑事责任**；
> 五年内不得重新取得机动车驾驶证。〔依据1〕
>
> 醉酒驾驶营运机动车的……十年内不得重新取得机动车驾驶证，重新取得后不得驾驶营运机动车。〔依据1〕
>
> 若醉驾导致交通事故，保险公司在交强险责任限额范围内**垫付抢救费用**，并有权向致害人追偿；
> 对受害人的**财产损失不承担赔偿责任**。〔依据4〕
>
> **参考文献：**
> 【依据1】《中华人民共和国道路交通安全法》(2021-04-29) 第九十一条 —— 饮酒后驾驶机动车的……
> 【依据4】《机动车交通事故责任强制保险条例》(2019-03-02) 第二十一条 —— ……

注意最后那段：**答案里的每一句都挂着依据编号，编号能翻回法条原文**。法条里没有的东西，
模型会明说「现行依据中未规定」，而不是编一条出来 —— 这是这套东西能不能给交管客服用的前提。

## 技术栈

| 层 | 选型 |
|---|---|
| 语言 | Python 3.11 |
| 向量库 | Milvus 2.6 —— 稠密 + BM25 双路召回，分词与融合都在**服务端** |
| 模型 | 生成 `qwen-max`／向量 `bge-large-zh-v1.5`（跑在本地 Ollama，OpenAI 兼容协议，换模型只改 `.env`） |
| 服务 | FastAPI + uvicorn，`/qa/stream` 走 SSE 流式 |
| Agent | LangGraph 状态机（**只用状态机**，LLM 调用直接走 `openai` SDK） |
| 依赖 | 基础组只有 3 个包：`openai` · `pymilvus` · `python-dotenv` |

分词、BM25、分页全推给 Milvus 服务端，所以本地不需要任何 NLP 或检索库 —— docx 解析也是
标准库 `zipfile` + `ElementTree` 直读，没引 python-docx。**能用标准库就不加包**是这个项目的一条主线。

## 项目结构

```
traffic_law_rag/
├── api.py  __main__.py  pipeline.py  config.py  contracts.py  server.py
├── kb/     建库四步：docx 进，Milvus 集合出（只在 build 时跑）
├── qa/     问答三步：改写 → 混合检索 → 强制引用式生成
├── agent/  Agentic RAG：模型自己规划查什么、查几轮
└── eval/   三套题集 + 一组双跑：hit@k / 规则取条探针 / 跨法多跳 / 单跳两臂对照

法规知识库/   docx（唯一真源）→ text → parsed → chunks → index
tests/        358 条，全部离线
data/         两套评测题集（跨法多跳那 63 道是模型生成的产物）
```

每个子包只按路径说话，**包内 `__init__.py` 一律不做 re-export** —— 要用哪个就 import 哪个。
`kb/` 一导出就会让「只想用切块器」的调用方连带拖上 pymilvus；`agent/` 一导出就会把 langgraph
拉进 `import traffic_law_rag`。这两条都有测试钉着。

## 想深挖

**[docs/DESIGN.md](docs/DESIGN.md)** —— 完整设计文档，适合想看清楚工程判断的地方：

- 七层管道每层的输入输出契约，以及为什么契约只认一个真源

- 一条结构性约束怎么变成**可执行的测试**：`qa/` 的三个内部件（检索器 / 生成器 / 改写器）只准被门面
  `qa/rag.py` 认识，用 AST 断言钉住 —— 这条约束在写成测试之前是假的：检索器那头有六处直接伸手
  取零件，生成器那头（后补的）有七处
- 踩过的坑，包括一个「不报错、不失败、只是悄悄劣化」的静默降级缺陷
